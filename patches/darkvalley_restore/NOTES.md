# Dark Valley and lab X18 restored to the original SoC

Maintainer reports: no bandits and no chest at the X18 entrance, the entrance door is locked, no snorks and no lab ambience in X18,
poltergeists with CoP effects and no corpse, the Dark Valley to Cordon transition and the Sidorovich quest are gone, and the fake gauss costs 5000 instead of the joke price.
Reference used: the original SoC 1.0006 `all.spawn` dumps of the levels (`alife_l04_darkvalley`, `alife_l04u_labx18`, `alife_l01_escape`) and the original scripts.
Rule: only what the original game has, no new features.

### Item 6 in detail
* `spawns/all.spawn` gets two objects (generated by `tools/make_all_spawn.py` from the owner's `coop.addon`; the addon is not modified): level changer `val_esc_level_changer` (SoC position, direction and size of `exit_to_escape`, destination Cordon game vertex 136 / level vertex 1900380 = the vertex next to `start_actor_02`) and the Cordon zone `esc_return_from_dv` (SoC position and size, logic in `esc_return_from_dv.ltx`).
* Raid start (the existing restrictor at the lab entrance): the trader message, the new task `val_start_get_out_via_south_gate_quest_task` (target = the new changer) and the flag `VAL_RAID_START`.
* Cordon: first arrival after the raid gives the Sidorovich message `esc_return_dv` and, after 20 game seconds, `ESC_RETURN_FROM_DV_INFO`, which unlocks the dialog `esc_smart_terrain_1_trader_sidorovich_x18_documents` (needs the three X18 documents of the party, they are NOT taken, reward 1000, once). Task `val_start_show_documents_to_sidorovich_quest_task` follows the dialog.
* The dialog is listed for Sidorovich in `patches/repeatable_quests/.../character_desc_coop_l01_escape.xml` (one `actor_dialog` line added there, that patch owns the file).

## X18 poltergeist crash with downed players (UNTESTED)
Report: silent dedicated-server crash in X18 while poltergeists live, after repeated knock-down / revive. Revive is engine side (no script handles it) and the
stack trace is not written, so the cause is not confirmed. Guard added in `coop_scn_valley_restore.script`: on coop_l04_x18 the server ticks every second; a player
with health below 0.3 counts as downed, and all poltergeists get `poltergeist_set_actor_ignore(true)` until every player has stayed above it for 6 s.
Not reproduced, not tested; if the crash remains the guard is not enough and the cause is inside the engine poltergeist code.

## Not done / limits
* The 13 one-shot `x18_sound_N` stingers of the X18 restrictors (SoC `[ph_sound]` per room) are not restored: the mod's restrictors have no logic and the original `x18_sound_N` to file mapping lives in the SoC `script_sound` config, which I could not read (the Steam SoC archives use an index compression the tools here cannot decode). The level ambience itself is restored.
* The original blocks the Garbage exit with the military after the raid; here both exits stay usable (the text of the trader message says it is blocked). Blocking it needs more spawn objects.
* The SoC `val_exit_gate` has a `ph_gate` logic (locked until the raid). The mod's gate is a plain physic object without logic; it is left as it is.
* SoC poltergeist `m_poltergeist.ltx` could not be read either; only the particle set difference between the CoP tele and flame variants is undone. The CoP `detection_*` block (screen effect when a poltergeist notices you) is still there.

## Conflicts with other patches
* `bind_monster.script` is the ONE merged file for three changes: (1) no poltergeist release on death plus the tele particle change (this patch), (2) the `coop_balance.on_npc_hit` call in the hit callback (soc_economy), (3) the `mutant_loot` hooks (client binder, dead-mutant tick, death roll instead of the add-on's ground drop of the part, alive-spawn reset). `mutant_loot` no longer ships its own copy; it needs this file, so ship both patches together. The mutant_loot hooks were added with `patches/mutant_loot/tools/gen_bind_monster.py` (it expects a file without them).
* `character_desc_coop_l01_escape.xml` is shipped by `repeatable_quests`: one line added there (see above).
* `squad_descr_pscale.ltx` (player_scaling) still has `x18_smart_terrain_4_m_poltergeist_tele_1_squad_ps`: regenerate with `gen_squads.py` after merging.
* Needs `cutscenes_core` (its Scene Director loads every `coop_scn_*.script`, that is how `coop_scn_valley_restore.script` starts) and `x18` (document checks of the dialog).
* `all.spawn` is a full copy (41 MB) of the addon file plus the two objects; no other patch may ship it. It also carries the Cordon bridge patrol paths of `patches\cordon_bridge` (chunk 3 only, 10 paths of `esc_smart_terrain_7_walker_*`): if this file is regenerated from the addon, run `patches\cordon_bridge	ools\make_paths.py` on the result again (see that NOTES.md).

## Tests (engine side, dedicated server + 1 real client, `tools/stalker_xrmpe/run_coop.ps1`)
Hooks in `tests/`: `dv_hooks.lua` (Dark Valley), `x18_hooks.lua`, `esc_hooks.lua` (Cordon). Merged gamedata = this patch + `cutscenes_core` (without its `xr_conditions.dscript`) + `repeatable_quests` character file; the hook files start the Scene Director themselves.
All lines below are PASS lines from the server or client `qa_assert.log`:

* 1 bandits: `val_smart_terrain_17` holds `val_smart_terrain_17_bandit_1_squad`, 6 members; the three military squads can be created at the same terrain afterwards (no crash, 25 s watch).
* 2 box: `val_equipment_box_01_case_0005` has 8 children: ammo_5.45x39_ap 2, ammo_12x76_zhekan 3, medkit 2, ammo_vog-25 1 (scan of all server objects with `parent_id` = box).
* 3 door: `alife():object("val_door_trader")` was found by the script (`door_found=true`) and is nil afterwards.
* 4 snorks and ambience: squad `x18_smart_terrain_4_m_snork_1_squad` = `snork_indoor_normal` + `snork_indoor_weak`, 0 poltergeists at 4_m, poltergeist squads of 1_m, 2_m, 3_m kept; client `level.get_weather()` = `x18_ambient`, whose ambient is `ambient_env_x18` (sound channel `ambient_env_x18_shoc_snd`).
* 5 corpse: a poltergeist created next to the player and killed is still a server object, online and dead 8 s later. A/B with the stock `bind_monster.script` in the same hook: no PASS in 70 s (the object is released at death).
* 6 transition: server object `val_esc_level_changer` (clsid 102) at -44.6 0.4 -548.8 and registered story id; Cordon zone `esc_return_from_dv` (clsid 145) at 304.3 15.7 5.4; running the real `on_actor_inside` condlist of the lab-entrance restrictor delivers the trader message (icon key `all_players_message_from_sidorovich`), sets `VAL_RAID_START`, gives tasks `val_start_get_out_via_south_gate_quest_task` and the Barman task; in Cordon the zone delivers `st_esc_return_dv` and sets `ESC_RETURN_FROM_DV_INFO` after the timer.
* 7 gauss: `dialogs_val_restore.if_actor_has_money_800` agrees with the player's money, the offer text says eight hundred.

Not proven in game (limits of the harness): the harness player in Dark Valley is created with the game vertex of Cordon (ALife keeps Dark Valley objects offline), so walking into the real restrictor and the real level change at the south gate could not be driven; the changer entity, its position and the condlists are proven, the travel itself is not. The Sidorovich dialog is proven only to the extent that the game boots with it (XML parsed, character file lists it); it was not opened with a talking player.
