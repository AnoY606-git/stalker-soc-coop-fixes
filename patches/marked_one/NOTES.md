# The Marked One as the story character

## Root cause (how the model is chosen)
- The lobby character list is `[coop_team] skins` in `configs/mp/cooperative_game.ltx` (`<skin>:<spawn section>`). `<skin>` is a mesh in `meshes/actors/stalker_mp/` (`mp_skins_path`) and also the UI icon id (torso icon, `ui_models_torso_addon.xml`). The first entry maps to `actor_the_main_character` (the gold-star "story character"); the rest map to `actor_partner_regular`. The mod shipped `stalker_neutral_blouse_1` (balaclava) as the story character.
- On spawn the skin becomes the player's visual (in-game log: `Skin - actors\stalker_mp\stalker_marked_one.ogf`), is replicated to every client like any skin, and `character_desc_selo.xml` / `spawn_sections.ltx` repeat the visual for the profile and section.
- Wearing an outfit replaces the visual with the outfit's `actor_visual` (outfit.ltx / outfit_soc.ltx). The mod pointed every outfit at generic CoP-multiplayer `player_*_outfit.ogf` meshes, so a worn suit no longer looked like the Shadow of Chernobyl hero.

## Lobby 3D model (the figure standing at the bottom left of the lobby)
- There is no separate lobby model setting. `coop_lobby_wnd.xml` only holds the 2D UI (portraits, buttons). The room with the bunk beds is part of the level, and the engine (xrGame.dll, `CUILobbyWndCOOP`, "RPoint for Visual", `norm_all_0_lobbyidle_%d` idle animation) stands the local player's skin there. So the figure is the `[coop_team] skins` entry of the player (the first one until another portrait is picked), i.e. `meshes/actors/stalker_mp/<skin>.ogf`.
- Proof (same lobby screenshot, only the first skin changed): balaclava skin shows the balaclava man, `stalker_hero_degtyarev_1` shows the long-coated Degtyarev, and the Marked One skin shows whatever mesh `stalker_marked_one.ogf` holds.
- The earlier `stalker_marked_one.ogf` was byte-identical to xrMPE's `actors\stalker_hero\stalker_hero_1.ogf`. That is NOT the SoC hero: Call of Pripyat's own player model (`actor.ltx` visual) is that file, i.e. Degtyarev's default look (jacket, short hair). SoC's own file for the Marked One is `actors\hero\stalker_novice.ogf` (`character_desc_general.xml`, `[actor]`/`[mp_actor]` visual): the hooded sand jacket.
- A raw SoC mesh cannot be used: it uses the SoC rig (45 bones, pelvis is the root with a 180 degree yaw), and xrRender_R4 crashes the client the moment the lobby creates it (reproduced). `tools/soc_hero_to_xrmpe.py` converts it to the xrMPE rig: two extra root bones (`root_stalker`, `bip01`) so every vertex bone id shifts by 2, new pelvis bind pose, mesh and bounding boxes turned 180 degrees about Y, and the CoP animation pack list. Textures `act_green_stalker1` and `act_stalker_face` already ship inside coop.addon.
- Rebuild: `python -I patches\marked_one\tools\soc_hero_to_xrmpe.py <SoC>\meshes\actors\hero\stalker_novice.ogf <xrMPE stalker_hero_1.ogf> stalker_marked_one.ogf` (the SoC file is read from the Steam SoC `gamedata.db4`, the donor from `game\patches\xrmpe_meshes_actors.db0`). Add `--tex-prefix mo_ --keep act\act_bandit,act\act_green_stalker1,act\act_head_mask,act\act_soldier,act\act_st_exoskeleton_tank,act\act_stalker_black` to rename the textures the way the shipped meshes have them.

## Not verified
- Walking, crouching and shooting of the converted meshes in third person were not looked at. The lobby idle animation, the idle pose seen from a second client, spawn and death were. The meshes use the same CoP animation packs and the same bone names as every other mp skin, but no script or console command in this xrMPE build presses movement keys, and posting window messages to the game is ignored, so the only way is real keyboard input on a visible window.
- The lobby figure follows the picked portrait because it is the player's skin (proof: changing the first `skins` entry changes the figure; in the 2-client run client B was given the story character and client A the second skin, and each saw the other with the matching model). Clicking CHARACTER and another portrait was not driven for the same reason.
- Worn suits that are not in the SoC table use the nearest SoC model (see the outfit mapping above); the Duty exo and Freedom exo suits use the exoskeleton, the three Clear Sky suits use the Clear Sky fighter bodies, Freedom heavy uses the light Freedom model (that is what SoC does), Duty heavy uses the Duty model.
- Equipping a second outfit while one is worn, and multi-client replication, were not run (one local player only). Visuals travel as the standard skin/outfit visual, so remote clients need the same patch (they do for the usual "Different versions" check).
- The new mesh must exist on every client (same patch on all).
