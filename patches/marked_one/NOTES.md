# The Marked One as the story character

## Root cause (how the model is chosen)
- The lobby character list is `[coop_team] skins` in `configs/mp/cooperative_game.ltx` (`<skin>:<spawn section>`). `<skin>` is a mesh in `meshes/actors/stalker_mp/` (`mp_skins_path`) and also the UI icon id (torso icon, `ui_models_torso_addon.xml`). The first entry maps to `actor_the_main_character` (the gold-star "story character"); the rest map to `actor_partner_regular`. The mod shipped `stalker_neutral_blouse_1` (balaclava) as the story character.
- On spawn the skin becomes the player's visual (in-game log: `Skin - actors\stalker_mp\stalker_marked_one.ogf`), is replicated to every client like any skin, and `character_desc_selo.xml` / `spawn_sections.ltx` repeat the visual for the profile and section.
- Wearing an outfit replaces the visual with the outfit's `actor_visual` (outfit.ltx / outfit_soc.ltx). The mod pointed every outfit at generic CoP-multiplayer `player_*_outfit.ogf` meshes, so a worn suit no longer looked like the Shadow of Chernobyl hero.

## Lobby 3D model (the figure standing at the bottom left of the lobby)
- There is no separate lobby model setting. `coop_lobby_wnd.xml` only holds the 2D UI (portraits, buttons). The room with the bunk beds is part of the level, and the engine (xrGame.dll, `CUILobbyWndCOOP`, "RPoint for Visual", `norm_all_0_lobbyidle_%d` idle animation) stands the local player's skin there. So the figure is the `[coop_team] skins` entry of the player (the first one until another portrait is picked), i.e. `meshes/actors/stalker_mp/<skin>.ogf`.
- Proof (same lobby screenshot, only the first skin changed): balaclava skin shows the balaclava man, `stalker_hero_degtyarev_1` shows the long-coated Degtyarev, and the Marked One skin shows whatever mesh `stalker_marked_one.ogf` holds.
- The earlier `stalker_marked_one.ogf` was byte-identical to xrMPE's `actors\stalker_hero\stalker_hero_1.ogf`. That is NOT the SoC hero: Call of Pripyat's own player model (`actor.ltx` visual) is that file, i.e. Degtyarev's default look (jacket, short hair). SoC's own file for the Marked One is `actors\hero\stalker_novice.ogf` (`character_desc_general.xml`, `[actor]`/`[mp_actor]` visual): the hooded sand jacket.
- A raw SoC mesh cannot be used: it uses the SoC rig (45 bones, pelvis is the root with a 180 degree yaw), and xrRender_R4 crashes the client the moment the lobby creates it (reproduced). `tools/soc_hero_to_xrmpe.py` converts it to the xrMPE rig: two extra root bones (`root_stalker`, `bip01`) so every vertex bone id shifts by 2, new pelvis bind pose, mesh and bounding boxes turned 180 degrees about Y, and the CoP animation pack list. Textures `act_green_stalker1` and `act_stalker_face` already ship inside coop.addon.
- Rebuild: `python -I patches\marked_one\tools\soc_hero_to_xrmpe.py <SoC>\meshes\actors\hero\stalker_novice.ogf <xrMPE stalker_hero_1.ogf> stalker_marked_one.ogf` (the SoC file is read from the Steam SoC `gamedata.db4`, the donor from `game\patches\xrmpe_meshes_actors.db0`). Add `--tex-prefix mo_ --keep act\act_bandit,act\act_green_stalker1,act\act_head_mask,act\act_soldier,act\act_st_exoskeleton_tank,act\act_stalker_black` to rename the textures the way the shipped meshes have them.

## What changed
- New skin `stalker_marked_one` (first entry, still `:actor_the_main_character`, so quests keyed on the story character are unchanged). Mesh = the original SoC hero model (`actors\hero\stalker_novice.ogf`) converted to the xrMPE skeleton (see above), shipped as `meshes/actors/stalker_mp/stalker_marked_one.ogf`. The other five faces (`stalker_neutral_blouse_2..6`) stay as optional partner characters.
- Icon: the SoC Marked One portrait (vanilla `ui_actor_portrets` at 246,870, 123x87) cropped into `textures/ui/ui_marked_one_icons.dds` (120x120 torso icon `stalker_marked_one`, plus 165x108 `ui_actor_p_stalker_marked_one`), registered in `configs/ui/textures_descr/ui_marked_one_icons.xml`. Upscaled from a small source, so it is soft; the maintainer can swap the DDS for a better crop.
- `character_desc_selo.xml` (main character visual) and `spawn_sections.ltx` (`[actor_the_main_character]` visual) point at the new skin.
- Outfits: `actor_visual` of 27 sections in `configs/misc/outfit.ltx` and 8 derived sections in `configs/misc/outfit_soc.ltx` now use the original SoC hero suit models (`actors\hero\*.ogf`), converted with the same tool and shipped as `meshes/actors/marked_one/*.ogf` (the CoP `actors\stalker_hero\*` meshes they used before are Degtyarev's bodies). Mapping follows SoC's own `outfit.ltx`: novice (+white novice) -> the skin mesh itself, stalker/tourist/ghost and CS light/mid -> `stalker_hood`, scientific (+Freedom scientific) -> `stalker_scien`, Duty scientific -> `actors\dolg\stalker_do_nauchniy`, ecolog/orange -> `stalker_ecolog`, ecolog green -> `stalker_chemical`, exo/Freedom exo/Duty exo/pnb-4uz/CS heavy -> `stalker_exoskeleton`, bandit/chainmail -> `stalker_bandit`, black coat and merc suits -> `stalker_killer`, Freedom light/mid/m2/heavy -> `stalker_svoboda_light`, Duty/hunter/heavy -> `stalker_dolg`, soldier -> `stalker_soldier`, military -> `stalker_military`, specops (+therapeutic) -> `stalker_specops`, monolith -> `stalker_monolit`. The mesh textures are the SoC originals extracted from the Steam SoC install and shipped as `textures/act/mo_*.dds` (+ bump files), because several `act_*` textures already in coop.addon or CoP differ from SoC's (same name, other content). Textures that are byte-identical to SoC's (`act_bandit`, `act_green_stalker1`, `act_head_mask`, `act_soldier`, `act_st_exoskeleton_tank`, `act_stalker_black`) are not duplicated.
- **outfit.ltx lives in `patches/bandit_jacket`** (that patch already overrides the file for the hud fix). I edited that single copy; this patch does not ship its own outfit.ltx. The two patches must be built together (build.py does).
- Not changed: hero hands in first person (`player_hud_section`), stray `actor_visual` key in `[sect_specops_outfit_therapeutic_immunities_add]` (outfit_soc.ltx, not a real outfit section, unused).

## How tested (real game, listen server, coop_l01_escape, test copy of coop.addon)
- Boot clean, no engine errors from the new files. Engine log: `Skin - actors\stalker_mp\stalker_marked_one.ogf`.
- Suit test (`suit_test.lua`, listen server): for each of the 35 outfit sections the worn outfit is released, the new one is created in the inventory (the engine wears it), `get_visual_name()` is read back and must equal the ini `actor_visual` and `item_in_slot(7)` must be that section. 35 of 35 PASS, no crash or engine error (33 in one run, the last two, `monolit_outfit` and `specops_outfit_therapeutic`, in a second run because the first ran out of soak time). `configs/models/capture/kombez_kupol_damage_med.ltx` (SoC original) had to be added: the Duty scientific mesh includes it from its user data and the client crashed without it.
- Third person: dedicated server plus two clients (`THIRD_PERSON_client_A_watching_marked_one_qab.jpg`, `THIRD_PERSON_client_B_watching_partner_qaa.jpg` in the results folder above): client A sees client B's story character as the hooded SoC Marked One, client B sees A as the second skin. Both players stand in the lobby state, so the view is the idle pose under the lobby overlay.
- Script probe in the running game (earlier build): player section `actor_the_main_character`, `get_visual_name()` = `actors\stalker_mp\stalker_marked_one`; after creating and equipping `novice_outfit` the visual became `actors\stalker_hero\stalker_hero_novice_1.ogf` (outfit swap works). Each other outfit's `actor_visual` read back from the live ini resolves to the intended hero mesh.
- Lobby 3D model, three runs of the same scene (`tools\stalker_xrmpe\results\lobby_marked_one_model\`): `BEFORE_lobby_cop_degtyarev_hero1_model.jpg` (old mesh: CoP Degtyarev), `REFERENCE_lobby_mp_degtyarev_skin.jpg` (the mp Degtyarev skin, for comparison), `AFTER_lobby_marked_one_model.jpg` (hooded SoC Marked One, idle animation plays, no tip lines in the description). The lobby is held with a test hook that suppresses the harness' hands-free respawn and takes engine screenshots; the screenshots in the usual run_coop flow show the world after spawn, not the lobby.
- With the converted mesh the player also spawned (`get_visual_name()` = `actors\stalker_mp\stalker_marked_one`), was killed by script and the game ran on for 25 s with no crash (ragdoll physics built from the converted IK data; Game Over screen shown).

## Not verified
- Walking, crouching and shooting of the converted meshes in third person were not looked at. The lobby idle animation, the idle pose seen from a second client, spawn and death were. The meshes use the same CoP animation packs and the same bone names as every other mp skin, but no script or console command in this xrMPE build presses movement keys, and posting window messages to the game is ignored, so the only way is real keyboard input on a visible window.
- The lobby figure follows the picked portrait because it is the player's skin (proof: changing the first `skins` entry changes the figure; in the 2-client run client B was given the story character and client A the second skin, and each saw the other with the matching model). Clicking CHARACTER and another portrait was not driven for the same reason.
- Worn suits that are not in the SoC table use the nearest SoC model (see the outfit mapping above); the Duty exo, Freedom exo and CS heavy suits all use the exoskeleton, Freedom heavy uses the light Freedom model (that is what SoC does), Duty heavy uses the Duty model.
- Equipping a second outfit while one is worn, and multi-client replication, were not run (one local player only). Visuals travel as the standard skin/outfit visual, so remote clients need the same patch (they do for the usual "Different versions" check).
- The new mesh must exist on every client (same patch on all).

## По-русски (кратко)
- Отдельной настройки модели в лобби нет: фигура внизу слева это скин игрока из `[coop_team] skins` (`meshes/actors/stalker_mp/<скин>.ogf`), игра ставит его в комнате с кроватями.
- Раньше `stalker_marked_one.ogf` был копией `actors\stalker_hero\stalker_hero_1.ogf`. Это модель героя Зова Припяти (Дегтярёв), а не Меченый.
- Теперь это оригинальная модель Меченого из ТЧ (`actors\hero\stalker_novice.ogf`, куртка с капюшоном), переделанная под скелет xrMPE (скрипт `tools/soc_hero_to_xrmpe.py`). Сырой файл ТЧ роняет клиент при создании модели.
- Костюмы: все 35 секций одежды (outfit.ltx, outfit_soc.ltx) теперь показывают соответствующие модели ТЧ из `actors\hero\*.ogf` (папка `actors\marked_one\`), переделанные тем же скриптом; текстуры ТЧ лежат как `act\mo_*`. Проверено в игре: надевание каждого костюма, имя визуала читается верно, падений нет.
- Проверено в игре: скриншоты лобби до/после, спавн и смерть, вид от третьего лица со второго клиента (стоит, анимация покоя). Не проверено: ходьба, приседание и стрельба в третьем лице, ручной выбор другого портрета (нет способа послать ввод в окно игры, не отбирая мышь у пользователя).
