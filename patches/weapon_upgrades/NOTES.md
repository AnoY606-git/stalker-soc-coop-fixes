# Weapon upgrades for every gun

Request: "not all guns have weapon upgrades". Only existing CoP upgrade trees are used.

## Boot-safety note (2026-10-19)
The first version also shipped `weapons_unique.ltx` (nimble/snag/luckygun variants, `pri_a17_gauss_rifle`). Those sections do NOT exist in the running game (checked with `section_exist` in game; spawning `wpn_g36_nimble` aborts even without any patch), so shipping the file created them half-configured and levels crashed with "Can't open section ''". The file and all references to those sections are removed; 75 weapons remain. Boot checks: Radar, X10, Agroprom, X16, CNPP-2, twice each, no crash (one Agroprom run only failed the harness presence compare, no crash).

## Audit (95 weapon sections, layers vanilla < xrmpe_cop_addon < xrmpe_patch < coop addon)
1. No upgrade tree at all: `wpn_fn2000` (+`_m1`, `_nimble`), `wpn_spas12` (+`_nimble`), `wpn_svu` (+`_nimble`), `wpn_lr300_m1`, `wpn_bm16_m1`,
   `wpn_colt1911_m1` (the add-on blanked `upgrades =`), `wpn_gauss`, `pri_a17_gauss_rifle`, `wpn_rpg7`, `wpn_rg-6`, `wpn_sig552`.
2. Dangling names (tree or `upgrade_scheme` that does not exist): `wpn_mp5sd`, `wpn_pmm`, `wpn_fort17`, `wpn_sig220r`.
3. Trees exist but nobody can apply them: the add-on's `misc/inventory_upgrades.ltx` `[upgraded_inventory]` (the engine only upgrades listed items) and the two technician
   item lists in `misc/stalkers_upgrade_info.ltx` (`[bar_smart_terrain_10_stalker_plyushkin]`, `[mil_smart_terrain_11_freedom_shurup]`; the engine passes the profile id as mechanic name,
   `inventory_upgrades.can_upgrade_item` checks `line_exist(mechanic, item)`) lack 48 weapons (all xrMPE CoP guns, the `_nimble`/`_snag` uniques, ...).

## Evidence (run_coop, dedicated, test hook `tools/test_hook_weapon_upgrades.lua`, PASS)
- All 75 sections: `upgrades` non-empty, every tree/element/upgrade section resolves in `item_upgrades.ltx`, in `[upgraded_inventory]`, and `inventory_upgrades.can_upgrade_item(w, mechanic)` is true for both technicians (447 upgrade slots checked).
- 15 weapons (every previously empty family, plus fiveseven/ak74) spawned in a player's inventory and one root upgrade installed through the server entity's upgrade list (STATE packet, the same path the save loader uses); engine read-back matched, server alive 7 s later.

- Not available from Lua: `install_upgrade` / `add_upgrade` are not exported by this xrMPE build, so the UI install path itself was not clicked.
