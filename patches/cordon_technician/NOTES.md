# Technician in the Cordon rookie village (coop_l01_escape)

Players asked for a mechanic (repair and CoP-style upgrades, like the Bar technician) in the starting area.

## Research: how the existing technicians work
- A technician is an NPC whose specific character has `<mechanic_mode>1</mechanic_mode>` (Bar: `bar_smart_terrain_10_stalker_plyushkin`,
  Army Warehouses: `mil_smart_terrain_11_freedom_shurup`). That makes the talk window offer Repair / Upgrade.
- The engine passes the character PROFILE id as the "mechanic name" to `inventory_upgrades.script`
  (`can_upgrade_item(item, mechanic)`, `precondition_functor_a`, `effect_functor_a`, `how_much_repair`). The data is
  `configs\misc\stalkers_upgrade_info.ltx`:
  - section `[<profile>]`: the item sections he can upgrade (a line per item);
  - optional section `[<profile>_upgr]`: `up_sect_xxx = false` (or a condlist) per upgrade; `false` makes `precondition_functor_a` return 1
    (not available). This is the mod's tier switch (the Yantar tech and the Jupiter/Pripyat leftovers use it);
  - optional `discount_condlist` with `mech_discount(x)`: price factor (Bar: commented out, so factor 1).
- Repair is not limited by the item list (`can_repair_item` only refuses the Gauss rifle). Price: `cost * (1 - condition) * 0.6 * factor`.
- Upgrade price = `cost` of the `up_sect_*` in `item_upgrades.ltx`; paid by `effect_functor_a` (server) / `effect_repair_item` (client).
- The Bar technician's logic is an `animpoint` job given by the smart terrain (`level_spot = mechanic` shows the PDA mechanic icon and sets the
  mechanic profession). NPCs in this mod come from `all.spawn` squads. We cannot edit `all.spawn`, so the new NPC is created by script.

## What was added
- `scripts/coop_scn_esc_technician.script`: server side `ensure()` creates one NPC with `alife():create("esc_rookie_technician", ...)`
  in the workshop house of the village (x -219.1, y -19.9, z -165.2, the nearest AI node of the spot, found at run time with `level.vertex_id`;
  game vertex from `esc_smart_terrain_1`). The house holds the tech-material items and a vise of the original map; it is 35 m from Sidorovich's bunker
  door, 14 m from the first-quest restrictor and 18 m from the nearest campfire, so no path or campfire spot is touched.
  - once only: the spawn section has a `story_id`, the story object registry is saved with the game, `ensure()` first looks the id up
    (`get_story_object_id`), then scans the entities by section (so a lost registry entry re-registers the existing NPC instead of creating a second one).
  - It is called by a never-firing scene `trigger` of the scene director (`coop_scenes.register`, polled every 500 ms on the server) which is
    loaded by the director's `coop_scn_*` discovery. Rate limited to once per 5 s. Needs `patches/cutscenes_core`.
- `configs/creatures/spawn_sections_coop_l01_escape.ltx`: section `[esc_rookie_technician]:stalker` (profile, story id, `custom_data` = his logic file).
- `configs/scripts/coop_l01_escape/esc_rookie_technician.ltx`: `[logic]` with `remark` (stands at the bench, `ward_noweap` arms folded pose),
  `level_spot = mechanic`, invulnerable, ignores combat, no weapon, `meet` section copied from the Bar technician.
- `configs/gameplay/npc_profile_addon.xml`, `character_desc_coop_l03_agroprom.xml` (specific character, `mechanic_mode`, visual
  `stalker_neutral_2_unique_3`, an unused unique model), `dialogs_coop_l03_agroprom.xml` (greeting + "What can you do for me?").
  The three files are existing, registered files nobody else patches. `character_desc_coop_l01_escape.xml` (repeatable_quests) and `system.ltx`
  (repeatable_quests) are owned by other patches, so new files could not be registered; ids are global, so the host file does not matter.
- `configs/misc/stalkers_upgrade_info.ltx`: mod file + two sections generated by `tools/gen_upgr.py`.
- `configs/text/eng|rus/st_cordon_technician.xml`: name "Stepan Gaika" / "Степан Гайка", bio, greeting:
  "Something broken? Put it on the bench. I patch up rookie gear and bolt on the simple upgrades."

## Prices and upgrade set (why)
- The mod supports tiers only through `<profile>_upgr` (`false` per upgrade). Rookie area = basic upgrades: every upgrade costing more than
  2000 RU is switched off (393 of 811 are off, 418 stay: the cheap half; the Bar technician allows all). Items: common Cordon gear only (pistols, 3 shotguns,
  MP5, AK-74U, AK-74, Abakan, novice and stalker suits, hardhat, respirator and their `_m1` variants).
- Prices are the cheapest the mod has: factor 1.0, no Freedom markup (Bar technician with the discount line commented out), repair at the standard 0.6 of the missing value.

## Not done / limits
- `coop_pda_phrases` (Archive sync of dialog lines) has no entries for his lines (the file is generated; the dialog works without).
- No trade table; he only repairs and upgrades. If he is killed by a script he is not replaced (he is invulnerable).
- No sound greeting (no voice files for him).
- Saves made before this patch get him on the next load (the guard only looks for an existing one).

## Crash review (2026-10-19, static analysis only, untested; STATUS.md: "crashes when the technician spawns, esc_rookie_technician13031")
No log of the crash was available, so the cause is **not proven**. Everything the spawn touches was read against the mod scripts
(`se_stalker`, `xr_motivator.net_spawn`, `bind_stalker_cl.net_spawn`, `smart_terrain.setup_gulag_and_logic_on_spawn`, `xr_logic.initialize_obj /
configure_schemes / activate_by_section`, `stalker_generic.reset_show_spot`, `xr_remark`, `xr_meet`, `sound_theme`, `trade_manager`,
`story_objects`) and the data (profile, specific character, visual, voice, dialogs, strings, spawn section, logic file). All of it is consistent
with the Bar mechanic Plyushkin (same character fields, same `level_spot = mechanic`, same meet section), the model and the voice folder exist,
the XML is well formed, the scheme `remark` accepts `target = nil`, the state `ward_noweap` exists.
What differs from every NPC that is known to work, and was changed in `coop_scn_esc_technician.script`:
1. **Mismatched level / game vertex.** The first version used the level vertex of the house but the game vertex of `esc_smart_terrain_1`, 35 m away.
   The engine keeps the NPC in the game graph under that game vertex (offline simulation, online switch); `sim_squad_scripted` always passes a pair
   that belongs together. Now the game vertex is the nearest game-graph vertex of the level to the spot (`game_graph():vertex(i):level_point()`),
   with the smart terrain's vertex only as a fallback.
2. **Created before any player actor was online.** The director only waits for a player to leave the lobby (3 s); `db.actor` / `db.mp_actors`
   can still be empty, and the binder (`initialize_obj`, meet, show_spot) runs at once for an NPC that is created next to the first player.
   Now `ensure()` waits for `db.mp_actors` to contain an actor.
3. **`se.angle = ...` after the create** (a property write on an entity that is already registered and broadcast): removed.
4. **No `db.spawned_vertex_by_id` entry**: `sim_squad_scripted:add_squad_member` sets it so `motivator_binder:net_spawn` places the NPC on the wanted
   node; now done too.
5. **Logic from `custom_data`.** In stock CoP the section line `custom_data = <file>` is a Level Editor default; if the runtime `alife():create` does
   not load that file the NPC has an empty `spawn_ini`, no `[logic]`, and stands without logic. `ensure_logic()` detects an online NPC without an
   active scheme on two ticks in a row and starts the same file the way `xr_logic.initialize_obj` does (`configure_schemes` with the file name, so
   a saved game restores it from the same file).
6. **Cost:** the 65534-object duplicate scan ran every 5 s until the registry knew him; it now only runs when the registry has lost him.
If the crash is still there, the first thing to read is the server log line `[esc_technician] created id=... lvid=... gvid=...` and the Lua error
after it. Fallbacks, in order of effort: create him as a one-member squad through `sim_board:create_squad` (the tested path of repeatable_quests
and player_scaling) with a job in `smart/esc_smart_terrain_1.ltx` instead of `custom_data`; or ship a full `all.spawn` entry (the file is already
carried by `darkvalley_restore`, so that must be merged there).
